# Parakeet Local development

The user's original brief is the product authority (cited as B§n). Read it at `.local/brief/original_brief.md` (kept outside Git because the repo is public; ask the user if it is missing), then `docs/requirements.md`, `docs/architecture.md`, and `docs/verification.md`, before substantial changes. Where a repo document contradicts the brief, the brief wins and the document is corrected. Follow the installed current Rust Playbook. Keep Domain and Application separate, application-owned capability/Queries/Writes ports, SQLx persistence and native/model adapters outside the core. Compose at CLI/desktop entry points. Do not add HTTP, Electron, a second business core, or unrelated Smaller Talk features.

Use `scripts/cargo` (the pinned Rust toolchain), `scripts/build-app`, and `scripts/run-desktop <existing-data-root>`. Runtime state is explicitly selected. Do not silently initialize/migrate storage or install weights. SQL stays in feature-local external files; `.sqlx` is committed and SQLX_OFFLINE defaults true. Regenerate with `scripts/prepare-sql` after query/schema changes.

The original MacParakeet database and recording folders are read-only source evidence. Never rename, repair, modify or delete them. Use the source snapshot importer, never migrate a source database. Keep all audio, transcripts, embeddings, names, local databases and model weights out of Git. The `.local` directory holds current private verification receipts and enrollment clips; `.references` contains inspected upstream repositories.

Never invoke a remote AI route without the user's explicit configuration/authorization. Do not infer that an arbitrary CLI is local. Model predictions and imported labels are never verified examples. Identifications and corrections the user explicitly confirms are, and they create reversible, inspectable voice examples (B§1, B§10). Reprocessing must retain original results, title overrides and corrections; unresolved timing stays unresolved.

Run relevant tests and `scripts/cargo clippy --workspace --all-targets -- -D warnings`. Distinguish simulated logic, real models, real recordings, hardware and human verification. Update measured results and limitations honestly. Microphone approval, physical keyboard behavior, M3 testing and personal voice identity have not been established merely by the existing automated tests.
