# Native UI performance observations

The harness follows Smaller Talk at `19d69563f979a8a80c311fbc0389453f440a390a`: explicit opt-in recording, isolated data, semantic phases, executable hashes, and nonsuspending Darwin `proc_pid_rusage` accounting. It reuses the same vendored GPUI profiler APIs rather than treating application render-construction time as frame latency. No provider, chat or service functionality was copied.

Build with `CARGO_BUILD_JOBS=2 scripts/build-app --release --performance`. The default build remains uninstrumented. Runtime observation requires an explicitly prepared directory; ordinary launches do not open an evidence channel. All output is local, and raw traces belong under ignored `.local/`.

```
python3 scripts/ui-performance.py prepare --out .local/performance/trial
PARAKEET_PERFORMANCE_DIR="$PWD/.local/performance/trial" scripts/run-desktop <isolated-existing-data-root>
python3 scripts/ui-performance.py record --out .local/performance/trial \
  --pid <app-pid> --binary '<absolute-bundle>/Contents/MacOS/ParakeetLocal' \
  --data-root <isolated-existing-data-root> --label baseline
python3 scripts/ui-performance.py phase --out .local/performance/trial --kind idle idle
python3 scripts/ui-performance.py phase --out .local/performance/trial --kind scroll long-transcript-scroll
python3 scripts/ui-performance.py stop --out .local/performance/trial
# Quit the app normally to flush its observer, then:
python3 scripts/ui-performance.py report --out .local/performance/trial
```

The recorder observes; phase commands do not perform UI actions. Native scrolling, navigation, finding and processing use the actual application controls. `PARAKEET_APP_BUNDLE` selects a preserved benchmark bundle when using `scripts/run-desktop`. It does not change database provisioning rules. `scripts/prepare-ui-fixture.py --directory <new-path>` generates a deterministic 2,000-segment transcript without audio or identities; import it through the ordinary `meetings import` operation.

Use the same window dimensions, data snapshot, page, text, model settings and scroll sequence on both builds. Mark idle, open, repeated down/up scrolling, find, inference and post-close phases. Wait for content and allow multiple resource samples. Repeat captures; warm filesystem/font caches, host load and trial order can affect the result. The harness is intended for targeted diagnosis, not an automatic release verdict.

Each resource sample records per-process RSS, physical footprint, cumulative user/system CPU time and process start identity. CPU percentages are interval deltas; 100% is one logical CPU. App descendants are tracked separately and observed reparented descendants retain their identity checks. Missing reads are recorded as failures, never zero usage. Summed footprint is accounting rather than deduplicated physical memory. GPU/ANE utilization is not fully observed.

The app records full GPUI draw phases, submission, frame work relative to the real refresh budget, dirty-to-present duration and cumulative input-to-frame latency histograms. Input histogram phase boundaries have up to one observer interval of uncertainty. Sparse input or manual pauses are not low FPS. Actual scrolling must produce at least ten frames and three observed offsets; empty/missing metrics remain null. CPU/frame statistics are instrumented observations, not proof of every displayed pixel or a physical keyboard test.

A bounded background writer handles trace files; the UI observer takes snapshots without forcing a redraw. Transcript text, names, audio and embeddings are not logged by the app observer. Numeric context includes segment/page counts, window bounds, pending work and scroll offset. Process paths and isolated data roots are still private local metadata. No trace is uploaded.

The candidate reader uses GPUI's variable-height `ListState`, with 300 points of overscan and measurement of only the rows near the viewport. It prepares corrected display state and case-folded search text in the background task that receives a recording, then recomputes matching indices only when data or find input changes. New results rebuild this derived state; original segments and corrections stay unchanged. Page/data/editor/word-evidence changes invalidate row measurements, preserving the logical top for content edits. The active editor's focus handle is registered with the list so scrolling does not strand an active input.

Copy transcript still exports the complete corrected recording, and row Copy exports its full segment independently of rendering. Native text selection operates on mounted rows; selection spanning rows while they are recycled and complete VoiceOver traversal need separate verification. A scrolling benchmark does not establish those behaviors.

CPU counters require Mach timebase conversion on Apple Silicon. This sampler converts ticks using `mach_timebase_info`; a controlled calibration compared converted CPU deltas against Python's process CPU clock. The initial baseline capture mislabeled raw Mach ticks as nanoseconds; its original samples remain intact and an explicit `accounting-correction.json` applies the measured 125/3 scale when regenerating that report. Frame/RSS/footprint measurements were unaffected. Apple's [rusage implementation](https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/kern/bsd_kern.c#L1187) assigns task power counters to these fields; the installed SDK and local CPU calibration were also inspected. A missing unit declaration now requires an explicit correction receipt rather than silently using the old numbers.

Measured on October 27, 2026 on the available 16 GiB Mac mini (`Mac14,12`), macOS 26.3.1. The [numeric report](../benchmarks/results/2026-10-27-native-ui.json) contains the executable hashes, phase counts, CPU/RSS/footprint percentiles and caveats. Baseline source was `a338ff5`; candidate was `dee5d11`; the final executable adds the Find-dismissal refresh fix. Each started from an isolated backup of the same 19-record library, including a synthetic fixture. The personal library remained at 18 recordings.

Each matched phase used 24 native wheel steps, down/down/up/up repeated six times, at 1240 × 878 points. The personal transcript has 593 current segments; older runs were not counted as current transcript length. The deterministic fixture has 2,000 segments with 80–160 words and variable paragraphs. Pagination remains 40 rows. Baseline has two valid personal repeats and three synthetic repeats; the candidate repeats those, and the final binary adds one repeat of each. An exploratory baseline phase with insufficient observed offsets is excluded.

| Workload | Baseline p95 frame work | Candidate repeats | Final recheck | Baseline → final p95 input latency |
|---|---:|---:|---:|---:|
| Long personal transcript | 13.59–14.69 ms | 3.19–3.36 ms | 3.25 ms | 19.79–19.82 → 9.78 ms |
| 2,000-segment fixture | 9.61–9.93 ms | 2.99–3.12 ms | 3.07 ms | 15.91–16.03 → 8.93 ms |
| Fixture while local ASR runs | 9.94 ms | 3.06 ms | — | 16.36 → 8.69 ms |

All matched baseline scroll frames exceeded GPUI's budget; none did in the candidate or final matched phases. The display reported a 6.944 ms refresh interval; GPUI applies an 8.333 ms budget floor. This does **not** prove sustained 144 Hz presentation. Opening and resizing still contain occasional frames above budget: final warm-open maxima were 11.13 ms for the personal transcript and 13.75 ms for the fixture. There is no claim that every interaction fits one refresh.

Sampled p95 CPU during personal scrolling was 53.1–53.9% of one logical CPU before, 24.5–26.1% in the candidate, and 25.7% in the final recheck. Synthetic scrolling was 34.3–38.2% before versus 12.4–16.0% after. These phases include manual pauses and input cadence changed as rendering became faster. Frame timings are the stronger comparison; CPU percentages are context. The host was busy with unrelated work, trial order was baseline then candidate/final, and no significance test or randomized comparison was performed.

Memory did not materially improve. Personal-scroll p95 footprint stayed approximately 95–96 MiB; synthetic phases were approximately 130 MiB before and 130–132 MiB after. During ASR the sampled phase p95 was approximately 490 MiB before and 505 MiB after. Post-processing small-recording footprint was 134.5 versus 141.5 MiB after different QA histories, with idle p95 CPU around 0.84% in both instrumented captures. These short observations neither establish a leak nor a long-session bound. Both public 634.578-second ASR runs completed with 46 segments, in 19.477 and 19.346 seconds; the reader optimization did not materially change inference throughput.

The resource sampler explicitly retained one baseline and three candidate read failures during inference. Missing reads were excluded, never treated as zero. All three captures finished normally with zero dropped UI samples. The candidate inference phase includes a trailing interval after completion; every drawn frame had a preceding observer sample with pending work, with the stated observation-interval uncertainty. Raw private traces, calibration, reports and build/test receipts are under `.local/performance/`.

These measurements used 40-row pages. On Oct 28, 2026 paging was removed so a transcript scrolls as one list in the same `ListState`; that change was first measured on a scripted 2,000-segment run on the same day (partial: scrolling 2.8 ms p95 work, but opening ~0.59 s, tab switches ~0.53 s and per-keystroke editing ~145 ms, because the list measured every row on each reset). The list no longer measures every row, and keystrokes re-measure only the edited line; those two fixes are verified by tests only and have not been re-measured. Native regression checks covered page 41–80, multiline save, an editor scrolled offscreen while retaining focus, correction-aware search and Undo. They found and repaired stale cached matches when Escape or the Find button cleared the field programmatically. Both dismissal paths were rechecked in the final release. Variable-height wrapping and scrolling were also checked at approximately 920 points wide. Only isolated synthetic content was edited. Full cross-row selection and VoiceOver coverage remain open.

A follow-up removes the application's permanent 100 ms activity timer. The loop starts with work, shuts down after completion, and restarts for later work. Settled idle performs no activity ticks or diagnostic JSON construction. An already scheduled final timer can drain within one interval after a short operation. Explicit `PARAKEET_UI_METRICS` observation intentionally keeps the diagnostic loop alive, with at most one asynchronous file write in flight. Capturing, dictation and model-progress feedback retain their active refresh path; actual microphone behavior was not newly exercised.

The [idle follow-up report](../benchmarks/results/2026-10-27-native-idle.json) contains two 25-second ordinary-release observations of the same quiet public transcript in the personal library. Process interrupt wakeups changed from 153.62/s to 144.51/s; CPU from 1.40% to 1.27% of one logical CPU. Memory was approximately 67–69 MiB. Package-idle wakeups increased in the later observation, which depends on other host work. These short sequential samples support a modest reduction in polling, not a battery-life or energy-saving percentage. The pinned macOS GPUI display-link implementation remains subscribed while a visible window is active, so residual regular callbacks require a separate framework-level investigation.

Prepared reader data now also indexes per-segment speaker attribution and the first 100 displayable word-evidence entries, rather than scanning all evidence for every visible row. Index creation runs in the existing background load task. Raw words, order, Unknown decisions and the existing display limit are preserved. A native public fixture retained exactly the same 17 segments, corrections, attributions and 231 words; 24 expanded-evidence scroll frames measured 3.63 ms p95 work, without a matched pre-change speed claim. Two real public-audio ASR jobs verified activity ticks 0 → 93 → quiet → 120 → quiet, with no ticks advancing in the settled idle phases. The instrumented capture finished normally with zero dropped samples; ordinary idle figures came from the separate uninstrumented release.
