# Review repairs

This pass addresses R1–R7 from [the project review](project-review.md), without changing personal model choices, verified examples or AI consent.

- Dictation uses an active-session drop guard. Stream error/EOF, explicit stop and caller abort cancel the session; normal exits await settlement. Cancellation interrupts an awaiting transformation. If cancellation races insertion, raw text remains retained and delivery is reported uncertain rather than claiming that nothing could have been inserted. Physical key/editor behavior remains a separate check.
- The legacy catalog uses a separate strictly read-only opener and one read transaction for schema and records, including live WAL state. Application-destination ownership checks remain strict. Blob and textual source UUIDs are supported.
- Schema 6 adds a current-transcript projection. Bounded excerpt jobs remain in immutable history and do not replace full-source results. Coordinated multi-source passes carry a publication group; a group is eligible only after all declared sources complete. An unfinished replacement keeps the previous eligible transcript. A deliberately requested single-source full pass remains independently eligible. Original untargeted imported text has no reliable source partition, so it is not arbitrarily mixed into new source output.
- Full-recording reprocessing records unavailable authoritative sources as failures, while preserving useful completed work. Its incomplete error carries named recording/run/source evidence, exposed by CLI `retained_result`.
- Library search uses current selected segments and effective correction snapshots, including Undo. It excludes stale raw history. The stored snapshots are produced by the correction service; raw evidence remains available in history.
- Benchmark composition uses the same guarded publication capability as other imports. A release-CLI test holds the exclusive storage gate and verifies that no recording is published.
- Public operations now have separate error contracts. Cleanup, job control, plan listing, scoring, media inspection, import planning and text/Markdown exports have operation-specific types. Cleanup/policy/meeting operations use named inputs. Processing/capture/enrollment inputs use explicit `XInput` names; serialization fields and CLI command syntax remain stable. Runtime cancellation controls remain separate execution context.

The existing six-package architecture remains. No HTTP, dependency-injection framework or second business core was added. SQL is feature-local/checked; view creation is an explicit migration. No ordinary command initializes/migrates storage.

The dictation test covers stream error, EOF, explicit stop and caller abort with synthetic capture and no real insertion/AI. CLI verifies the benchmark gate. Default Clippy, SQLx offline preparation/check, formatting and signed ordinary release build pass. Existing optional cache/decoder/native-fixture probes remain separate.

A six-second public audio file produced real local ASR, followed by a completed bounded excerpt; the full transcript's segment IDs remained selected. The native app rendered that same preserved transcript. These are source/runtime and publication checks, not new speech-quality, microphone, physical-keyboard, M3 or personal-identity acceptance.

The following integrated-workflow pass will test and apply that transition with a backup.
