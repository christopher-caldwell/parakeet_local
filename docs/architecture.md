# Architecture and decisions

`parakeet-domain` owns observed values, validation, chronology, gesture transitions, compatible voice matching, and evaluation math. It has no runtime or provider dependencies. Serde is a neutral representation helper and UUID supplies deterministic imported IDs.

`parakeet-application` owns focused feature services, capability contracts, and persistence Queries/Writes. `parakeet-database` implements SQLx operations and explicit database provisioning/migration. `parakeet-infrastructure` owns artifact/file access, FFmpeg, models, subprocesses and macOS adapters. Binary entry points explicitly compose the graph. There is no service locator or generic repository.

Database lifecycle is explicit: create an empty local database, then migrate it. Ordinary reads, desktop startup, and doctor never create or migrate a database. SQLite does not have PostgreSQL owner/runtime roles; that part of Playbook migration guidance does not apply. A local single-user database uses foreign keys, WAL, a busy timeout and short atomic mutations.

Imported source records have UUIDv5 identities based on original source identity; local new operations use UUIDv4. Imported snapshots are preserved, and re-import does not overwrite local title overrides or manual corrections. Original source labels are claims without confirmed identity. Source kind is never a person identity.

Reference inspection (October 27): Playbook 0.3.0; Smaller Talk HEAD 19d69563f979a8a80c311fbc0389453f440a390a (GPUI pre 0.3.9, Rust 1.99.1, SQLx 0.8.6 and local frame-memory patches); Control Tower current clone and ADRs 0004–0006; MacParakeet current clone and artifact v1 contract. Control Tower's shared-core rule is retained; its HTTP entry point is not required here. Only the relevant GPUI foundations are vendored and reused.

The complete FluidAudio package requires Swift tools 6.0; installed Swift is 5.8.1. A minimal, attributed Nemotron source subset now builds independently with that compiler, alongside speakrs and whisper-rs. Measured comparisons drove the diarization preset choice; see audio-models.md and verification.md. Model installs are deliberate commands; processing cannot trigger downloads.

Application services have operation-specific Inputs/Results/Errors and own both capability and Queries/Writes ports. Binary entry points own environment configuration, tool paths, data roots and explicit composition. SQLx checked external query files are compiled against committed offline metadata. The variable-schema MacParakeet reader uses runtime SQL only for whitelisted third-party schema projections; database ownership/migration PRAGMAs are operational introspection exceptions.

An application_id marker guards the writable database boundary. Earlier development databases are recognized only by the exact initial migration checksum. Ownership is checked through a read-only connection before enabling WAL or migrations. Foreign databases are rejected unchanged. Source reads use their own read-only snapshot adapter and do not pass through application provisioning.

SQLite atomic imports, terminal run settlement and compare-and-append correction/suggestion revisions handle CLI/desktop concurrency. A single native capture lease and a single global model lease per data root prevent unsafe overlap across processes. Capture and inference leases are independent. Concurrent dictation during an owned meeting capture is currently rejected; a model-busy dictation retains its audio/text and reports failure. There is no priority queue or cross-process in-memory model server.

Application-owned processing ownership and recovery ports now distinguish abandoned jobs from live owners. Per-run file leases use the canonical database path, are acquired before publishing a running row, and protect terminal settlement. Explicit recovery conditionally marks unowned protocol-aware rows interrupted; retry creates a linked new run with the same pinned model/request. Older unmanaged rows remain untouched. No schema migration was needed: the existing interrupted status and versioned JSON configuration support this behavior. See [processing recovery](processing-recovery.md).

GPUI owns forms, navigation, focus, rendering, copy actions and transient task feedback. Tokio runs application calls; blocking model work uses blocking workers or bounded native subprocesses. The render thread does no decoding, inference, model hashing or SQL work. Native helpers write separate source CAF and sidecars with host-clock offsets, bounded buffers and capture-health evidence. A parent-death watchdog releases orphan event taps; capture EOF/timeout and restricted recovery preserve interrupted audio.

Audio location changes use an application-owned identity reader and conditional locator Writes port. The filesystem adapter streams hashes; SQLx changes only the saved track JSON when it still matches the expected row. No original file mutation or new source identity is involved. Native cluster inspection/editing, recovery and relinking all invoke the same services as CLI.

Model context caching is an infrastructure concern, bounded to one ASR and one embedding context per process with idle expiry and verification-aware invalidation. No model SDK types enter the core. Text insertion returns an explicit method/verification receipt; its recovery capability is application-owned and composed separately from database initialization. Private native clipboard journals protect transient typed snapshots; GUI startup and CLI use the same recovery service.

Read-only evaluation-file scoring has an application-owned reader and shared service; Domain owns bounded cpWER and speaker permutation. Optional word-timing requests are capability-checked and persisted, and old requests default to segment timing. Infrastructure groups native token bytes without interpolating time; Domain validates local bounds and derives meeting time from authoritative track metadata. Library returns word attributions separately from segment evidence/corrections; these anonymous predictions never enroll an identity.

The native presentation is split into `desktop::ui` (tokens, assets and keyboard-aware controls), `desktop::shell` (navigation, activity, errors and confirmations), and `desktop::library` (list/reader/forms). Input subscriptions debounce searches and reject stale generations; ordinary UI actions still invoke application services directly. Domain resolves immutable correction history for both the reader and exports, including an explicit Unknown speaker state independent of text. Desktop-owned cancellable playback tasks preserve the application playback boundary; infrastructure owns temporary decoded-file cleanup. See [UI behavior and verification](ui-ux.md).

`desktop::reader` owns a prepared presentation document: raw application detail plus resolved per-row corrections and case-folded display text, prepared in the existing background result task. GPUI state owns the filtered original indices and variable-height `ListState`; the 40-row page, correction IDs and full application export remain authoritative. The feature-gated `desktop::performance` observer and external macOS sampler are explicit local development tooling, not telemetry or application services. See [performance measurements and remaining selection/accessibility limits](ui-performance.md).

`desktop::activity` owns the temporary refresh loop for active work. Task launch starts it once; completion lets it stop, and a later task restarts it without treating the idle gap as UI latency. Explicit diagnostic observation can keep it alive, with serial asynchronous writes. Prepared reader data also owns source-order evidence indices; no evidence-resolution or persistence responsibility moved into rendering.

`application::meeting` orchestrates capture and durable final transcription through the existing capture/processing services. Its application-owned `MeetingFinalizationWrites` port conditionally replaces one recording metadata field; the SQLx adapter keeps that SQL feature-local. Atomic capture import publishes a pending plan with audio before inference. Canonical-database file leases serialize each controller, while correlated source runs allow checkpoint recovery without repeating completed sources. Native session sidecars retain intent for explicit partial-capture recovery. CLI and GPUI invoke the same controller; record-only dictation remains separate. See [meeting workflow](meeting-workflow.md).

`application::processing_control` owns semantic progress, cancellation observations and Queries/Writes. An owned processing driver retains its per-run lease through worker exit and terminal persistence independently of its caller. SQLx conditionally arbitrates cancellation and output publication; native adapters retain SDK/child ownership. GPUI observes the same durable run state without inference or SQL on the render thread. See [processing control](processing-control.md).

Whisper checkpoint validation and source hashing stay within the infrastructure adapter. Application retry/finalization supplies the prior compatible run identity; a new processing run remains the durable publication unit. Versioned source/model/request-bound chunks are rehomed to the new run, and semantic segment IDs are remapped without applying prior corrections to new evidence. No new persistence schema or entry-point business core is involved. See [continuation](chunk-resume.md).

`domain::storage` defines age/ownership/human-evidence retention decisions. `application::storage` joins narrow Queries with a metadata-only inspection capability and returns observational usage/preview results; it exposes no cleanup capability. SQLx owns schema-4 policy persistence with conditional revisions and source/reference projections. Infrastructure accounts for file identities, links and bounded traversal. GPUI renders background-prepared aggregates and bounded rows through the same service as CLI. See [storage scope and evidence](storage.md).
