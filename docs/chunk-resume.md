# Validated Whisper chunk continuation

`jobs retry RUN_ID` now reuses compatible completed Whisper chunks. Meeting finalization also links its latest unfinished source run, so `meetings finalize RECORDING_ID` can continue that source while retaining already completed sources. CLI and native retry actions invoke the same application services. Prior runs, raw evidence, title overrides, manual corrections and confirmed examples remain separate. Reused segments receive the new run's deterministic IDs; corrections are not silently transplanted onto them.

New checkpoints use version 2. Each private, durably published file binds its payload to the source content SHA-256/size, complete source-track snapshot, exact ASR request, pinned model revision and verified weight-file fingerprints, runtime configuration, chunk index, decoded length, requested local origin, raw output and original segment ownership. A SHA-256 over the exact serialized payload detects corruption without relying on floating-point JSON round trips. This is a local integrity check, not cryptographic authentication against a malicious owner of the data directory. Version-1 files remain preserved evidence and trigger a fresh pass rather than reuse.

Before reuse, the adapter streams a fresh source hash with a fixed buffer and cancellation checks. A completed run rechecks content before publication. Saved source hashes/metadata that no longer match fail processing. Checkpoint incompatibility instead records `metrics.resume.status = restart_required` plus a reason and performs a fresh source pass. No compatible files produces `unavailable`. The source/model/request/timing/ownership checks apply to every completed file before any prefix is reused. Only a contiguous prefix is accepted; partial files are ignored. Unexpected entries, symlinks, corrupt checksums, missing indices or excessive data refuse reuse. Reads are bounded to 120 files, 8 MiB per file and 64 MiB total.

Codec padding requires two clocks. The original decoder can return 59.988 seconds for a requested 60-second AAC window. Continuation preserves its requested next window origin **and** actual decoded duration; it does not shift the next source interval to close the 12 ms difference. Only the existing decoder's short-read tolerance (100 ms) is eligible. Actual word/segment evidence remains unchanged. Larger duration discrepancies cause a fresh pass. Source alignment that was unknown remains unknown. A relink or source-track metadata change currently also requires fresh processing, even if content bytes are identical.

Validated prefix chunks are published under the new run with remapped segment IDs before new inference starts. A second interruption therefore has a self-contained prefix and does not need to traverse a growing chain of ancestors. Cancellation still publishes no partial transcript. Complete runs report source-run identity, reused chunk count, actual reused audio milliseconds, requested timeline position and number of newly inferred chunks. The native Processing history shows reused work and explains incompatible-checkpoint fallback.

## Measured evidence

On one 634.578-second public AAC file, cancellation after two chunks, another interruption after four saved chunks, and final continuation produced the same 46 transcript texts/times as an uninterrupted run from the same release binary. The final attempt reused 239,976 ms of decoded audio at a 240,000 ms requested timeline position and inferred seven remaining chunks. Its engine wall time was 9.486 seconds versus 12.100 seconds for the uninterrupted pass. This is one paired workflow observation on one busy Mac; it is not a general speedup or accuracy guarantee.

A separate 89.285-second public synthetic speech fixture resumed its first 60-second chunk with experimental word timing enabled. Words and their timing/Unknown states matched uninterrupted inference. Deliberately corrupting that isolated checkpoint's checksum caused zero reuse and a successful full pass with matching text/times. A native retry reused four chunks and completed with matching text/times, preserving the title and prior run IDs. A source-aware meeting fixture separately verifies finalization linking, a 1250 ms source offset and title preservation. Raw probabilities may differ at insignificant floating-point serialization digits; exact raw-JSON identity is not claimed.

Unit tests cover private/durable/no-replacement files, source/model/settings/track/runtime mismatches, checksum corruption, legacy format, segment ownership, explicit speaker-claim refusal, gaps/symlinks/size bounds, repeated interruption, actual codec-padding clocks, cancellation during hashing and unknown origins. Application/SQLite tests verify compatible source retry linkage in meeting finalization. The opt-in real-model cache probe checks reuse, word-mode switching, invalid verification refusal and idle expiry using separate local model copies. Private receipts live in `.local/chunk-resume/`; the portable numeric report is `benchmarks/results/2026-10-27-chunk-resume.json`.

Nemotron and speakrs still restart their requested interval. Changes to model/settings or older checkpoints may save no work. Hashing adds local disk reads, checkpoint storage grows until explicitly managed, and the application still lacks a priority queue, live preview and retention controls. No original MacParakeet source or external AI route is changed by this feature. Microphone/physical keyboard/M3/personal identity checks remain separate.

Next independent step: storage accounting and an explicit retention policy with a preview, preserving original sources, verified examples and active/recoverable work. It can be implemented with current knowledge; choosing a personal cleanup policy and executing it should remain deliberate user actions.
