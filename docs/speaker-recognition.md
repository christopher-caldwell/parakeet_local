# Speaker learning and corrections

A detected cluster is anonymous and run-local. Microphone and system are acoustic sources, not identities. The reader uses same-track interval coverage and leaves turn-spanning/overlapping segments ambiguous; it does not invent word-level attribution. Possible cross-source lexical duplicates are flagged, not deleted.

Profiles have stable UUIDs and user-controlled names. Enrollment requires explicit confirmation of a clean 3–30 second source interval. Only confirmed examples are eligible for matching; no suggestion, acceptance, rejection, or clustering edit enrolls a new example. Removing a profile removes its stored voice examples and clears foreign-key identity references while preserving evidence/history.

Embeddings record exact weights revision, runtime/backend, preprocessing version and capture domain. Incompatible vector spaces and microphone/system/file domains are excluded. Similarities are averaged across compatible references per profile. Repeated enrollment of an identical interval/model is idempotent, and overlapping references on the same source are not counted as independent evidence. The explicit policy requires a minimum score, separation from the next identity, and verified example count. Otherwise the result is Unknown. There is no globally approved personal recognition threshold. CLI/UI summaries expose dimensions and provenance rather than raw vectors.

A real short-sample test exposed padded-silence contamination in the upstream single-window embedding call. The adapter now masks unused parts of its ten-second window, normalizes each usable window and pools multiple windows rather than silently truncating a long enrollment. The `masked-window-v1` revision prevents mixing earlier vectors with corrected vectors. Samples with less than three decoded seconds, nonfinite vectors, zero norm or insufficient energy are rejected.

The original strict public smoke test remains recorded as a failure: score 0.665 for the same voice versus 0.699 for a different one. Masking changed these to 0.873 versus 0.824, but the unchanged 0.9 policy still rejected both. No threshold was lowered just to pass that regression. A separate LibriSpeech probe selected policy on designated tuning utterances and evaluated disjoint held-out utterances: 5/6 known examples accepted correctly, all 6 unfamiliar examples Unknown, no observed false acceptances. CPU and Core ML matched on that tiny clean read-speech probe. It does not establish meeting-domain calibration or cross-device identity accuracy.

Suggestion receipts persist interval, model/version, policy, scores and resolution history without embedding vectors. Acceptance requires an explicitly selected transcript segment on the same recording/source fully covered by the evidence interval, and atomically appends its correction with the resolution. Broader segments need deliberate listening/manual correction. Rejection never poisons a profile. Undo appends history and detects intervening edits. Independent segment text/identity corrections also compare-and-append revisions to prevent lost CLI/GUI updates.

Cluster split/merge/undo commands produce derived diarization runs linked to earlier evidence; they never rewrite raw model output. Split times are meeting times. Merges are restricted to the same source. Repeated undo restores successive earlier states. Manual segment identities remain separate and reprocessing reports corrections whose original segment IDs no longer map safely.

The desktop supports preparing nonoverlapping candidates, playing source intervals, profile creation/rename/removal, confirmed enrollment, example review/removal, and segment corrections. Detailed suggestion-resolution and cluster-edit workflows are currently CLI surfaces. Those operations use the same application services and durable data, but corresponding full desktop controls remain independent follow-up work.
