# Speaker learning and corrections

A detected cluster is anonymous and run-local. Microphone and system are acoustic sources, not identities. The reader uses same-track interval coverage and leaves turn-spanning/overlapping segments ambiguous; it does not invent word-level attribution. Possible cross-source lexical duplicates are flagged, not deleted.

Profiles have stable UUIDs and user-controlled names. Examples come only from the user's explicit confirmation, never from a model prediction or an imported label:

- manual enrollment of a clean 3–30 second interval;
- **naming a whole cluster** (`speakers identify-cluster`, or Speakers → Identify voices), which corrects every segment the cluster speaks alone, lists overlapping or already-corrected segments untouched, and admits up to three clean single-turn windows as examples;
- accepting or replacing a suggestion (the compared interval becomes an example);
- assigning a person to a clean single-speaker segment of at least three seconds.

Each admitted example records an `origin` (`verified_by: user_identification`, the action kind and its ID), is capped at five per person per recording, is listed and removable under the person, and disappears when the action that admitted it is undone (`speakers undo-identification`, `speakers undo`, or undoing the suggestion decision). Rejections, Unknown and text edits admit nothing. If no model or clean speech is available the decision still applies and the reason is reported. Removing a profile removes its stored voice examples and clears foreign-key identity references while preserving evidence/history.

Embeddings record exact weights revision, runtime/backend, preprocessing version and capture domain. Incompatible vector spaces and microphone/system/file domains are excluded. A person's score is the cosine to the re-normalized centroid of their compatible references (`centroid-cosine-v1`, recorded on every saved decision), so adding varied correct examples does not lower the score the way averaging per-example cosines would. Repeated enrollment of an identical interval/model is idempotent, and overlapping references on the same source are not counted as independent evidence. The explicit policy requires a minimum score, separation from the next identity, and verified example count. Otherwise the result is Unknown. There is no globally approved personal recognition threshold. CLI/UI summaries expose dimensions and provenance rather than raw vectors.

A real short-sample test exposed padded-silence contamination in the upstream single-window embedding call. The adapter now masks unused parts of its ten-second window, normalizes each usable window and pools multiple windows rather than silently truncating a long enrollment. The `masked-window-v1` revision prevents mixing earlier vectors with corrected vectors. Samples with less than three decoded seconds, nonfinite vectors, zero norm or insufficient energy are rejected.

The original strict public smoke test remains recorded as a failure: score 0.665 for the same voice versus 0.699 for a different one. Masking changed these to 0.873 versus 0.824, but the unchanged 0.9 policy still rejected both. No threshold was lowered just to pass that regression. A separate LibriSpeech probe selected policy on designated tuning utterances and evaluated disjoint held-out utterances: 5/6 known examples accepted correctly, all 6 unfamiliar examples Unknown, no observed false acceptances. CPU and Core ML matched on that tiny clean read-speech probe. It does not establish meeting-domain calibration or cross-device identity accuracy.

Suggestion receipts persist interval, model/version, policy, scores and resolution history without embedding vectors. Acceptance requires an explicitly selected transcript segment on the same recording/source fully covered by the evidence interval, and atomically appends its correction with the resolution. Broader segments need deliberate listening/manual correction. Rejection never poisons a profile. Undo appends history and detects intervening edits. Independent segment text/identity corrections also compare-and-append revisions to prevent lost CLI/GUI updates.

Cluster split/merge/undo commands produce derived diarization runs linked to earlier evidence; they never rewrite raw model output. Split times are meeting times. Merges are restricted to the same source. Repeated undo restores successive earlier states. Manual segment identities remain separate and reprocessing reports corrections whose original segment IDs no longer map safely.

The desktop supports preparing nonoverlapping candidates, playing source intervals, profile creation/rename/removal, confirmed enrollment, example review/removal, segment corrections and saved identity-comparison review. Comparison requires an explicit similarity, separation and verified-reference count; no personal policy is installed until one is calibrated from verified examples. It displays alternative scores as similarities, not probabilities. Predicted and confirmed identities remain visibly distinct.

The shared `review_suggestion` use case supplies current transcript segments fully covered by a comparison's source interval, using the same coverage rule as resolution. The desktop can play that evidence, confirm a proposed identity, replace it with an explicitly selected person, reject the comparison or undo its decision. These actions never enroll a reference. Late results from another recording are ignored. CLI `speakers review-suggestion ID` exposes the same eligible speech and receipt. Anonymous cluster split/merge and undo controls are available in both CLI and GPUI.

A native desktop probe exercised accept → undo → reject → undo → replace → undo against labeled public audio in an isolated library. Corrections/resolutions persisted through the shared service, and the verified example count remained one. The fixture compared an utterance with its own enrollment, so this tests UI/data flow only and makes no recognition accuracy claim. Private receipts remain under `.local/suggestion-ui/`.

The native Speakers screen separates profiles/examples, anonymous clusters and identity comparisons. Cluster controls show the recording/source and selected processing run; they can preview clean nonoverlapping activity, split at an explicit meeting timestamp, merge selected clusters and undo derived edits. These operations never name a person or enroll an example. Native public-audio verification restored the original two-cluster partition after split/merge/two undo steps, retaining ASR and raw diarization evidence.

Cluster candidates pool all clean (no other speaker active), edge-trimmed turns of at least 1.5 seconds, longest first, up to 60 seconds, so a speaker who only has short turns can still be compared. No cluster is dropped for ordering reasons.
