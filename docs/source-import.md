# Read-only MacParakeet import

The installed MacParakeet CLI reports 5.1.0. Its actual `health --help` and `meetings list --help` were inspected. Configuration has no `meetingArtifactsFolder` override, and the real default artifact root was inspected. The live database was opened using SQLite `mode=ro`; no bare database-file copy was made. It contains six meeting records and four YouTube records. Artifact-folder UUIDs differ from transcription UUIDs, so imports use `manifest.meeting.id`, not the folder name, as the original identity.

Initial artifact audit: **six meetings**, five with microphone audio, five with system audio, five with both, all six with alignment metadata and diarization claims (five with usable retained-source alignment), one with both original audio tracks missing. All retained sources are M4A. Durations: 764941, 1679116, 1777388, 2839414, 2961352, 5571013 ms. One system track's capture metadata implies 25294634 ms but its actual decoded duration is 1637099 ms; the importer retains the original metadata and emits a discrepancy warning.

The importer reads v1 manifest/transcript/alignment sidecars and both current and legacy microphone/system names. Native captures additionally use CAF. Imported speaker labels stay unverified and source attribution stays unknown unless the artifact actually supplies usable source evidence. Original raw JSON is saved independently of normalized segments. Malformed/unsupported folders yield diagnostics instead of invented rows. Bad timing is retained as untimed text. Missing files remain explicit track records.

Six artifact records were imported into `.local/app/parakeet.db`; a second import produced zero new rows and six existing rows. The live database adapter subsequently added the four media records and recognized the six meetings as already imported. Track locators reference read-only original files to avoid copying the collection. Size/mtime fingerprints are checked before decoding or playback. These detect ordinary changes, not adversarial equal-size/mtime edits. Source JSON hashes and all artifact size/mtime values were inventoried in the private `.local/source-baseline.json`; final verification compares them again. Originals are never renamed, repaired, deleted, or migrated.

The new database is independently provisioned and migrated. Re-import is additive and idempotent, so it cannot overwrite local title overrides, model runs, or corrections. A changed original is deliberately not silently refreshed into an old identity. A missing/moved reference must be inspected and explicitly relinked in a future locator update workflow; automatic path repair is not implemented.
