# Evaluation methodology

The Rust scorer partitions a common timeline at all reference/prediction boundaries and excludes configured collars around reference boundaries. Reference overlaps are scored by default. Speaker mapping is a recording-wide maximum-overlap one-to-one Hungarian assignment. DER counts missed reference speaker time, false speaker time, and speaker confusion; its denominator is reference speaker time, so DER can exceed 100%. JER uses a separate maximum-IoU assignment and averages reference-speaker errors. Unmatched speakers remain errors. Empty reference speech has undefined DER. Scores are not rounded internally.

Public development material: [VoxConverse 0.3](https://github.com/joonson/voxconverse), Chung et al., *Spot the conversation: speaker diarisation in the wild*, Interspeech 2020. The official repository states CC BY 4.0 research availability; source video copyright remains with its owners. `scripts/prepare_voxconverse.py` selects the three shortest 20–120 second development recordings with at least two labeled speakers, deterministically, and fetches only those entries from the official ZIP using HTTPS ranges. Neither audio nor personal data is committed. This tiny deliberately short-turn diagnostic subset does not estimate full-corpus accuracy.

A suite declares dataset, split, reference status, exact input paths, models, collar and overlap handling. Reports record audio/reference SHA-256, runtime/model revisions, configuration, failures, timestamps, decoding/loading/wall time, real-time factor (processing seconds/audio seconds), and process-lifetime peak RSS on macOS. The latter is not isolated per-job memory and does not capture all Core ML helper-process memory. CPU/GPU/ANE utilization is not yet measured.

Personal recordings are unverified diagnostic data until a person supplies identity/turn ground truth. Imported labels are never used as accuracy references. Suite validation rejects ground-truth scoring of explicitly unverified personal data. Thresholds have no approved universal default; CLI suggestions require an explicit score and margin. Public development clips can support tuning; a separately designated held-out suite must remain untouched by that tuning before any broader claim.

WER uses Levenshtein edit distance. A suite explicitly selects exact whitespace tokens (the backward-compatible default) or english_case_punctuation normalization: lowercase, preserve alphanumeric characters and apostrophes, split other punctuation, collapse whitespace. Numbers are not semantically rewritten. Reports record the normalization and reference word count; aggregate WER is reference-word weighted. The JFK smoke uses exact tokens; LibriSpeech uses the declared orthographic normalization. This is not speaker-attributed WER; that remains unsupported without verified word/speaker alignment.

The three shortest qualifying VoxConverse test clips (fuzfh, msbyq, xkmqx) were held out from preset selection; the selection receipt predates those runs. LibriSpeech recognition fixtures interleave chapters where available, use two enrollment utterances for each of three known dataset speakers, one designated tuning utterance per known/unfamiliar speaker, and two disjoint held-out utterances for each of six speakers. The score policy is fixed before collecting held-out scores. These small subsets are deliberately diagnostic, not estimates of population false-acceptance rates.

ASR development uses six disjoint labeled public utterances (212 normalized reference words) for a base/small comparison. Base was retained on the development tie before six separate held-out utterances (201 words) were scored. The held-out comparison is reported without retuning that decision. Larger corpora, adverse acoustics and personally corrected transcripts are needed before a personal accuracy preference is established.
